# استكشاف الأخطاء وإصلاحها

## `OpenCode v2 was not found`

ثبت OpenCode v2 بنفسك من المصدر الرسمي ثم افتح طرفية جديدة. تحقق من `opencode --version` أو أن الملف `~/.opencode/bin/opencode` موجود. لا يحاول مثبت الوكلاء تثبيت OpenCode نيابة عنك.

إذا ظهر OpenCode في طرفية تفاعلية فقط، فقد يكون مساره محملاً من ملف shell غير تفاعلي. شغّل المثبت من طرفية يكون فيها الأمر متاحاً أو أصلح PATH بنفسك. لا يحرر المثبت ملفات shell.

## `OpenCode v2 is required` أو إصدار CLI غير مدعوم

تحقق من أن الأمر المستخدم هو النسخة المقصودة ومن أن الإصدار الرئيسي 2. لا يستبدل السكربت نسخة V1 أو نسخة مثبتة بواسطة مدير الحزم. عالج وجود النسخة القديمة يدوياً وفق وثائق OpenCode.

## فشل تنزيل أرشيف GitHub

تأكد من اتصال الإنترنت، ومن أن المستودع والفرع `main` عامان، وأن عنوان `raw.githubusercontent.com` وGitHub غير محجوبين. أعد المحاولة لاحقاً. لا تشغّل نسخة تنزيلها غير مكتمل.

## `Package manifest mismatch` أو فشل بصمة SHA-256

هذا يعني أن ملفات الحزمة لا تطابق بيان الملفات أو أن نسخة جزئية/معدلة استُخدمت. نزّل النسخة من فرع المستودع الرسمي مجدداً ولا تعدل ملفات الوكلاء داخل الحزمة قبل التثبيت. عند المساهمة، أعد توليد manifest وفق الإجراء المعتمد في المشروع ولا تحدث بصمة منفردة يدوياً.

## لا يمكن تحرير JSON / JSONC

يحافظ المثبت على ملفات JSONC ولا يكتب فوق إعداد ملتبس. استخدم:

```bash
curl -fsSL https://raw.githubusercontent.com/Alqudimi/ather-agents/main/install.sh | bash -s -- install --no-depth-2
```

بعدها أضف `experimental.subagent_depth: 2` يدوياً إلى ملف JSONC الفعّال، مع الحفاظ على مفاتيحك وتعليقاتك. لا تستبدل ملف الإعداد كاملاً بمثال المشروع.

## وجد أكثر من ملف إعداد في مستوى الأسبقية نفسه

راجع ملفات `opencode.json` و`opencode.jsonc` في جذر المشروع وداخل `.opencode/`. أزل الالتباس يدوياً أو استخدم `--no-depth-2`. لا يختار المثبت ملفاً عشوائياً.

## تعارض ملف وكيل موجود

المثبت لا يستبدل ملفاً محلياً مختلف المحتوى. احتفظ بنسخة احتياطية، ثم قرر يدوياً دمج الملف أو تغيير اسمه/مساره. إعادة التثبيت لا تتجاوز الحماية.

## `verify` لا يرى الوكلاء أو يعيد قائمة runtime ناقصة

1. شغل الأمر من جذر المشروع أو استخدم `--project`.
2. نفذ `opencode --version` وتأكد من v2.
3. نفذ `opencode debug agents` من نفس جذر المشروع.
4. تحقق من أن الملفات تحت `.opencode/agents/` وأن manifest سليم.
5. أعد تشغيل OpenCode/الجلسة بعد التثبيت إذا كانت الجلسة قديمة.

## الإلغاء ترك ملفات أو سجل حالة

هذا مقصود عند اكتشاف تعديل أو تعذر استعادة إعداد بأمان. راجع مسار السجل الذي يطبعه الأمر، وافحص رسائل `preserved changed...`. انسخ الملفات قبل التنظيف اليدوي. لا تحذف سجل الحالة قبل أن تتأكد من كل ملف يتتبعه.

## `No install record` عند الإلغاء

المثبت يزيل فقط ما يملك له سجلاً، ولا يخمن الملفات. تحقق من HOME و`XDG_STATE_HOME` نفسيهما المستخدمين عند التثبيت، ومن أنك اخترت مسار المشروع ذاته. لا تحذف الملفات يدوياً إذا لم تتأكد من ملكيتها.

## طلب المساعدة

قبل فتح بلاغ، أرفق نظام التشغيل وإصدار Python وإصدار OpenCode والأمر المنفذ ونص الخطأ كاملاً بعد إزالة أي مسارات أو بيانات حساسة. لا ترفق مفاتيح API أو سجلات جلسات خاصة. راجع [SUPPORT.md](../SUPPORT.md).
